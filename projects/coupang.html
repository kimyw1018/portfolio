쿠팡 WING 쿠폰 자동 갱신 스크립트

즉시할인 쿠폰을 조회·폐기·재발급하는 Node.js/TypeScript CLI

Coupang WING(입점사 관리 시스템) Open API를 호출해 매일 운영해야 하는 "즉시할인 쿠폰"을 폐기하고 새로 발급하는 작업을 자동화하는 CLI 스크립트입니다. TypeScript 소스 6개 파일, 총 494줄, 커밋 3건으로 하루 안에 설계부터 구현까지 끝낸 단독 프로젝트입니다.

TypeScriptNode.jsAxiosHMAC-SHA256Discord Webhookdotenv
01Role
기획부터 Coupang Open API 연동, 서명 생성, 실패 알림까지 전체 코드베이스(src/config, src/services, src/utils, src/index.ts)를 단독으로 설계하고 작성했습니다.
02Architecture
01

엔트리포인트: src/index.ts가 설정을 로드하고 서명 생성을 1회 테스트 출력한 뒤, --run 플래그가 있을 때만 실제 롤오버를 실행한다. 반복 실행(매일 자동 트리거)은 이 스크립트 범위 밖이며 외부 스케줄러(cron 등)에 의존하는 구조다.

02

오케스트레이션: CouponManager.runDailyRollover()가 "활성 쿠폰 조회 → 개별 폐기 → 신규 발급" 3단계를 순서대로 실행한다.

03

외부 연동: CoupangService가 API 호출과 응답 파싱을, signature.ts가 서명 생성을, DiscordService가 오류 알림을 각각 담당한다.

03Implementation
01

커스텀 HMAC-SHA256 서명: Coupang Open API가 요구하는 CEA algorithm=HmacSHA256 서명 인증을 서드파티 라이브러리 없이 Node 내장 crypto 모듈로 직접 구현했다. 타임스탬프(YYMMDDTHHmmssZ)·HTTP 메서드·경로·쿼리스트링을 한 문자열로 조합한 뒤 비밀키로 HMAC 서명하고, 매 요청마다 새로 계산해 재사용하지 않는다.

02

계약 ID 캐싱 + 다단계 Fallback: 신규 쿠폰 생성에 필요한 contractId를 (1) 인스턴스 캐시 → (2) 환경변수 → (3) 계약 목록 API → (4) 단일 계약 조회 API 순으로 조회한다. 모든 경로에서 값을 못 구하면 .env에 직접 지정하라는 안내와 함께 예외를 던진다.

03

단계별 실패 격리 오케스트레이션: 1단계(조회)와 3단계(신규 발급)가 실패하면 알림 후 즉시 전체를 중단하지만, 2단계(폐기)는 쿠폰 1개씩 개별 try/catch로 감싸 일부 쿠폰 폐기가 실패해도 나머지 쿠폰 폐기는 계속 진행한다. "조회·발급 실패는 그날 운영 자체가 불가능하지만, 일부 폐기 실패는 감내할 수 있다"는 판단을 반영한 구조다.

04

환경변수 Fail-Fast 검증: .env 값이 비어있거나 .env.example의 placeholder(your_...)를 그대로 두고 실행하면 기동 시점에 즉시 [Configuration Error]로 알리도록 검증했다.

04Problem Solving
01

API 엔드포인트·요청 스펙 전면 교체: 최초 구현은 openapi v4 경로와 ISO 8601 날짜, couponName/discountType 필드명을 사용했다. 4분 뒤 커밋에서 경로를 fms v2/v1로, 날짜 포맷을 쿠팡이 요구하는 커스텀 문자열("YYYY-MM-DD HH:mm:ss")로, 필드명을 name/type으로 전면 교체하고 쿠폰 생성 요청에 contractId를 필수로 추가했다. 정확히 어떤 응답 에러를 받았는지 로그로 남기지는 못했지만, 문서만 보고 추정했던 최초 스펙이 실제 API 스펙과 달랐다는 것을 diff로 재구성해 바로 다시 확인하고 구현을 교체했다.
