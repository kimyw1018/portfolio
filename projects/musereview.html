Security & Auth 토큰 탈취 차단

소셜 로그인 시 Access Token이 브라우저 히스토리에 남던 문제

쿼리 파라미터로 토큰을 넘기던 구조를 1회용 인가 코드와 HttpOnly 쿠키로 바꿨다.

문제

초기 구현은 리다이렉트 URI 쿼리 파라미터에 Access Token을 실어 프론트엔드로 전달했다. 이 방식은 브라우저 히스토리, 프록시 로그, Referer 헤더에 토큰 평문이 남아 탈취와 XSS 공격에 취약했다.

해결

리다이렉트 시에는 30초짜리 1회용 임시 인가 코드만 전달하고, 프론트엔드가 백엔드 POST API로 이 코드를 제출해 토큰을 교환하도록 흐름을 바꿨다. Refresh Token은 HttpOnly, Secure, SameSite=Strict 쿠키에 담아 XSS로 접근할 수 없게 했다.

결과: 브라우저 단 토큰 노출 경로 제거, 안전한 OAuth 2.0 인증 흐름 수립
Collaboration & DX 가이드 문서화

API 연동 질문이 반복되며 생기던 병목

폴더 구조 가이드와 Swagger 테스트 시나리오, 에러 페이로드 규격을 문서로 정리했다.

문제

API 연동이 본격화되자 프론트엔드 팀원들의 파일과 디렉터리가 제각각 생겨 충돌이 잦았고, 소셜 로그인의 토큰 발급 흐름과 예외 상황에 대한 질문이 반복되어 양쪽 개발이 지연됐다.

해결

노션에 디렉터리별 역할과 관심사 분리 기준을 트리 다이어그램으로 정리해 컨벤션을 통일했다. 소셜 인가 코드 발급부터 토큰 갱신까지 Swagger로 테스트하는 단계별 시나리오를 문서화하고, 도메인별 에러 코드와 메시지 페이로드를 명시해 프론트엔드가 바로 예외 처리를 구현할 수 있게 했다.

교훈: 지식을 문서로 정리해 전달하면 팀의 커뮤니케이션 비용이 줄어든다
Redis & Session 세션 무효화

로그아웃해도 살아있던 JWT를 즉시 무효화하기

Redis 블랙리스트로 Stateless JWT의 즉시 파기 문제를 보완했다.

문제

JWT는 한 번 발급되면 유효기간이 끝나기 전까지 서버가 강제로 무효화할 수 없는 Stateless 구조다. 사용자가 로그아웃하거나 탈취가 의심되는 상황에서도 이미 발급된 Access Token은 살아있었다.

해결

Redis에 Refresh Token을 저장하고 TTL로 만료를 관리했다. 로그아웃이나 탈퇴 요청 시 잔여 만료 시간만큼 Access Token을 Redis 블랙리스트 키로 등록하고, JwtAuthenticationFilter에서 블랙리스트 검증을 가장 먼저 실행해 탈취된 토큰의 접근을 즉시 차단했다.

결과: Stateless JWT의 확장성을 유지하면서 즉각적인 세션 파기 보장
