프로젝트 개요 및 기여 내용

악기 연주 피드백 플랫폼 뮤즈리뷰의 백엔드 초기 아키텍처 수립, OAuth 2.0 기반 소셜 인증 체계 구축, 그리고 프론트엔드 협업 생산성을 위한 표준 API 응답(ApiResponse) 및 전역 예외 처리 체계 설계를 전담했습니다.

사용 기술

Core Framework

Java 17, Spring Boot, Spring Security, JPA

Security & Cache

OAuth 2.0, JWT, Redis

Database & Tools

PostgreSQL, MariaDB, Docker

주요 구현 및 기술적 기여

A. OAuth 2.0 / JWT 다중 소셜 로그인 & Redis 세션 관리

  • • 다중 프로바이더 통합: 카카오, 구글 소셜 인가 코드 교환 및 사용자 조회를 단일 파이프라인으로 통합
  • • Dual Token & Redis 블랙리스트: 단기 Access Token과 장기 Refresh Token 구조를 적용하고, Redis TTL로 만료 관리. 로그아웃 시 Redis 토큰을 즉시 무효화하여 탈취 방어
  • • 인증 필터 체계: OncePerRequestFilter 상속 JwtAuthenticationFilter로 매 요청 토큰 검증 및 Context 주입

B. 표준 API 응답 & 전역 예외 처리 체계 (apipayload)

  • • 공통 응답 규격 (ApiResponse<T>): 성공 여부, 코드, 메시지, 결과를 감싸는 단일 응답 레코드 및 정적 팩토리 메서드 제공
  • • 도메인별 에러 코드 인터페이스화: BaseCode 인터페이스, CommonStatus 및 외부 AI 분석 서버 연동 오류 격리를 위한 AiServerErrorStatus 구축
  • • 전역 예외 처리기: @RestControllerAdvice 기반의 GlobalExceptionHandler를 통해 커스텀 예외를 일관된 포맷으로 클라이언트에 매핑 반환

트러블슈팅

1. 소셜 로그인 리다이렉트 시 Access Token 평문 노출 위험

• 문제: Redirect URI 쿼리 파라미터에 Access Token을 실어 보낼 경우 브라우저 히스토리 및 프록시 로그에 토큰이 노출되어 XSS 등 보안 취약점 발생.

• 해결: 리다이렉트 시 HttpOnly, Secure 쿠키에만 Refresh Token을 탑재하고, 1회용 임시 인가 코드만을 전달한 뒤 프론트엔드가 안전한 POST API 요청으로 Access Token을 발급받도록 구조 전면 개선.

2. API 공통 응답 래핑 시 타입 안정성 저하 문제

• 해결: ApiResponse<T>를 제네릭 레코드로 선언하고 정적 팩토리 메서드로 컴파일 타임에 반환 타입을 강제하여 런타임 캐스팅 오류 원천 방지 및 일관된 에러 JSON 반환.
