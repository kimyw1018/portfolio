💡 개요: 악기 연주 피드백 플랫폼 뮤즈리뷰의 백엔드 초기 아키텍처 수립, OAuth 2.0 기반 소셜 인증 체계 구축, 그리고 프론트엔드 협업 생산성을 위한 표준 API 응답(ApiResponse) 및 전역 예외 처리 체계 설계를 총괄했습니다.

1. 주요 구현 내용 및 기술적 기여

A. OAuth 2.0 / JWT 기반 다중 소셜 로그인 및 토큰 관리

  • 다중 프로바이더 통합: 카카오 및 구글 OAuth 2.0 프로토콜을 연동하여 인가 코드 교환 및 사용자 프로필 조회를 하나의 파이프라인으로 단일화
  • Dual Token & Redis 세션 관리: 단기 Access Token과 장기 Refresh Token 구조를 적용하고, Redis에 TTL을 설정해 만료를 자동화. 로그아웃/탈퇴 시 Redis 토큰을 즉시 삭제(블랙리스트 처리)하여 탈취 방어
  • 인증 필터 체계: Spring Security의 OncePerRequestFilter를 상속한 JwtAuthenticationFilter로 매 요청마다 토큰 유효성 검증 및 유저 인증 객체 주입

B. 패키지 기반 표준 API 응답 및 전역 예외 처리 체계 (apipayload)

  • 공통 응답 규격 (ApiResponse<T>): 성공 여부, 응답 코드, 메시지, 결과 데이터(result)를 제네릭으로 감싸는 단일 응답 레코드 정의 및 정적 팩토리 메서드 제공
  • 계층별 에러 코드 인터페이스화: 상태 코드 규격을 강제하는 BaseCode 인터페이스, CommonStatus 및 외부 AI 분석 서버 연동 오류 격리를 위한 AiServerErrorStatus Enum 구축
  • 전역 예외 처리기: @RestControllerAdvice 기반의 GlobalExceptionHandler를 통해 최상위 커스텀 예외 GeneralException을 가로채 클라이언트가 파싱하기 쉬운 일관된 포맷으로 매핑 반환

C. 백엔드 초기 환경 셋업 및 인프라 구성

  • 단방향 의존성 구조화: Controller - Service - Repository - Entity - DTO 간의 계층형 의존성 흐름 확립
  • Docker Compose 가상화: 로컬 개발 환경 일치를 위해 MariaDB/PostgreSQL 및 Redis 컨테이너 구동 자동화
  • Swagger API 스키마 사전 배포: 프론트엔드가 화면을 구현할 때 블로킹이 발생하지 않도록 명세서 선제적 제공

2. 기술적 트러블슈팅 (Deep Dive)

Issue 1

소셜 로그인 리다이렉트 시 Access Token 노출 위험

상황 및 원인: 소셜 인가 코드를 받아 검증한 뒤 최종 Access Token을 프론트로 넘길 때, Redirect URI의 Query Parameter에 실어 보낼 경우 브라우저 히스토리 및 프록시 로그에 토큰 평문이 노출되어 XSS 등 탈취 위험 발생.

해결 과정: 인증 성공 후 프론트엔드로 리다이렉트할 때는 HttpOnly, Secure 쿠키에만 Refresh Token을 탑재. Access Token은 URL에 일절 노출시키지 않고, 1회용 임시 인가 코드만을 파라미터로 전달한 뒤 프론트가 안전한 POST API 요청을 호출하여 발급받도록 구조 전면 변경.

결과: 브라우저 히스토리에 토큰이 노출되는 보안 취약점을 완전히 제거.

Issue 2

API 공통 응답 래핑 시 타입 안정성 저하 문제

상황 및 원인: 결과 데이터가 없는 Void, 단일 DTO, 리스트 등 다양한 반환 타입이 존재하는 상황에서 Object 타입으로 래핑할 경우 런타임 캐스팅 에러 위험 및 컴파일 시점의 불일치 감지 불가.

해결 과정: ApiResponse<T>를 제네릭 레코드로 선언하고 정적 팩토리 메서드(onSuccess, onFailure)에서 제네릭 타입을 강제 주입. 예외 발생 시에는 GeneralException 내부의 BaseCode를 추출해 ApiResponse<Void> 형태의 통일된 실패 포맷 반환.

결과: 컨트롤러 단에서 단 한 줄로 일관된 응답 리턴 가능, 컴파일 타임 타입 검증 및 프론트엔드 파싱 무결성 확보.
