세 번의 실패 끝에 바꾼 녹화 아키텍처

캔버스 통짜 합성의 프리징, 크래시, 화질 문제를 웹캠 단독 캡처 구조로 해결했다.

배경

발표자의 웹캠 영상과 슬라이드 자료를 브라우저에서 실시간으로 기록하고 서버에 업로드해야 했다. 처음 함께하는 팀원들과 진행한 프로젝트였고, 다뤄본 적 없는 미디어 녹화 영역을 직접 맡았다.

세 번의 시도

1차, 캔버스 통짜 합성 녹화. 슬라이드와 웹캠을 캔버스 하나로 합쳐 실시간 녹화했다. 녹화 시간이 길어지면 브라우저가 멈췄고, 5분이 넘으면 수백 MB 비디오 업로드 도중 타임아웃이 나서 저장이 실패했다.

2차, 합성 영상 청크 분할 전송. 전송 부하를 줄이려고 청크 단위로 잘라 보냈지만, 무거운 캔버스 화면을 브라우저에서 통째로 인코딩하는 연산 자체에서 메모리가 폭증해 탭이 꺼졌다.

3차, 인코딩 품질 저하. 용량을 줄이려고 해상도와 비트레이트를 낮췄더니 슬라이드 글자가 뭉개져서 발표 연습이라는 핵심 기능 자체가 무의미해졌다. 출시 일정이 얼마 남지 않은 상태에서 연달아 막혔다.

해결

통짜 캔버스 녹화를 버렸다. 용량이 큰 웹캠 영상(480p Blob)만 독립적으로 가볍게 녹화해 1MB 청크로 순차 전송하고, 슬라이드는 영상 인코딩 없이 넘긴 시점의 타임스탬프만 텍스트로 따로 모았다. 재생 화면에서는 비디오 재생 시간에 맞춰 슬라이드 이미지를 매칭하도록 다시 설계했다.

결과: 화질 저하 없음, 브라우저 크래시 0건, 업로드 타임아웃 0건. UMC 9기 데모데이 최우수상 수상
Network & Stream 타임아웃 0건

대용량 영상 업로드가 자꾸 끊기던 문제

3단계 1MB 청크 순차 업로드 파이프라인으로 안정화했다.

문제

모바일이나 불안정한 Wi-Fi에서 수십에서 수백 MB짜리 녹화 영상을 단일 HTTP POST로 보내면, 패킷이 유실될 때 녹화본 전체가 사라지고 413 또는 504 타임아웃이 발생했다.

해결

업로드 세션 초기화, 1MB 단위 Blob 청크 순차 스트리밍, 서버 조립 완료 트리거의 3단계 파이프라인을 구성했다. Axios의 onUploadProgress로 진행률 바를 표시하고, 청크 실패 시 최대 3회 지수 백오프로 재시도했다.

결과: 대용량 영상 업로드 실패율 0%
State Architecture 밀리초 동기화

슬라이드, 대본, 댓글이 서로 어긋나던 문제

Zustand 단일 상태와 이진 탐색으로 밀리초 단위 양방향 동기화를 구현했다.

문제

비디오 재생 중 슬라이드 넘김, 대본 스크롤 위치, 특정 초에 달린 익명 피드백 댓글이 서로 다른 컴포넌트 상태로 흩어져 있어 리렌더링 지연과 화면 엇갈림이 발생했다.

해결

Zustand 스토어에 비디오 재생 시간(currentTime)을 단일 상태로 선언했다. 타임스탬프 배열에서 현재 시간에 맞는 슬라이드 인덱스를 이진 탐색으로 O(log N)에 찾고, 사용자가 댓글이나 대본 줄을 클릭하면 그 시간으로 비디오가 바로 이동하도록 만들었다.

결과: 60fps 타임라인 재생, 컴포넌트 간 상태 불일치 버그 0건
